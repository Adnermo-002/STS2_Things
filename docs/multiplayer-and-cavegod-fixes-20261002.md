# 1.10.2：房主配置与活体巨岩显示修复

## 多人配置

此前配置从各自本地文件读取，只在配置一致时能保证相同生成结果。现在房主通过游戏的可靠网络通道发送完整配置；新局开局前发送最终快照，客户端确认收到后才生成房间。

- 房主决定全部配置，队员的写入不会覆盖房主设置。
- 玩法在开局后锁定，房主音乐开关仍实时同步。
- 读档使用房主打开存档前的配置；重连取得正在进行的战局快照。已生成的地图与遭遇队列不重抽。
- 本地偏好与会话覆盖分开保存，退出、断开或加入失败后恢复个人设置；BaseLib 普通保存和延迟保存均受保护。
- 配置包含协议与键顺序校验，拒绝非房主消息、旧消息、非法值和局内玩法变更。
- 怪癖草蜢奖励规则改为在所有客户端一致注册，按实际遭遇判断是否工作，不再受启动时的个人开关影响。
- 检查了商人猜拳的成交路径：沿用原生购买与奖励同步，实际扣款、卡牌、遗物和药水继续通过原版同步接口发送。

版本同步升至 1.10.2，原版联机握手会阻止与 1.10.1 混连。所有玩家仍需使用相同游戏版本和模组包。

## 活体巨岩

截图中的血条错位来自固定遭遇槽位与放大后的骨骼位置不一致。渲染复现中，左右血条与拳头横向分别偏离约 97 像素。血条、受击区域现在跟随各自拳头的世界坐标，按真实骨架缩放调整位置；命中特效中心也移回拳头范围内。

败北时手臂残留在遮罩上方，来自手臂与生物 UI 的绝对正 Z 层级。整个背景组合现在位于原版界面之下，手臂在背景内使用相对层级，血条回到原版 UI 层。抓取时仍保持手掌盖住玩家、偷取卡牌被拳头压住的关系。

“老化”提示移除岩石铠甲的大卡牌预览，保留覆甲/格挡的文字说明；击倒手臂发放 0 费岩石铠甲的玩法保留。

额外发现并修复：抓取恢复代码会给死亡角色发送 Idle 动画。现在保留死亡姿态，战斗结束时停止跟踪与释放 Tween，并清理偷取卡牌展示，避免尸体再次移动或界面重新淡入。

## 验证方式

- `scripts/test-things-config.ps1`：在 V107.1、V111 的真实程序集上验证配置权限、序列化、确定性生成、玩法锁定、音乐、重连、退出恢复和个人文件隔离。
- `scripts/test-config-network.ps1`：三个独立 Godot 进程通过真实 ENet 连接。房主与两个队员使用冲突配置，比较三种地图的 Boss、15 个精英、事件列表与后续 RNG；再测试音乐同步和一名队员真实断线重连。三端生成摘要一致。
- BaseLib/RitsuLib 探针：验证真实配置库的绑定、客户端权限，以及 BaseLib 延迟保存不会覆盖个人文件。
- `scripts/test-cavegod-ui.ps1`：真实 Spine 背景与原生生物血条渲染。测试 0.60 / 0.75 / 1.00 缩放及多个左右臂动作，检查命中点、卡牌预览类型、死亡恢复和覆盖遮罩的像素。
- `tools/CaveGodProbe`：复查 A0/A10、1/2/4 人的阶段血量、回合循环和意图伤害，断臂清理、成长、裂痕、晶脉、抓取/破爪、扫击偷牌、满手牌回退、眩晕、中毒、反伤和强制死亡。回归通过。

修复前渲染探针能明确报出：两个血条偏位、大卡牌预览、3392 个采样点穿过遮罩，以及死亡角色被切回 Idle。修复后这些断言通过。
