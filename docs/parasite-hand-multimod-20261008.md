## 实测结果

全部六个手牌核对点通过：

1. 开场8张牌、3能量，寄生1费；模型顺序、可见顺序和费用一致。
2. 通过鼠标选寄生，再移到出牌区域并释放／确认，实际消耗成功；能量3→2，消耗堆0→1，无空位残留。
3. 生成测试寄生与杂技，杂技抽到10张满手后，鼠标选择寄生并确认弃牌；寄生离手、弃牌与出牌区清理正常。
4. 第二回合：垂丝蛾缠丝生效、洞胃投食后正常抽牌，手牌费用与顺序一致。
5. 第三回合：洞胃吞牌、水蛭补牌后正常进入玩家回合，手牌无残留节点。
6. 第四回合：手牌、费用、能量与回合推进正常。

证据文件夹为 `fullmods-opening`、`fullmods-mouse-parasite-play`、`fullmods-acrobatics-discard`、`fullmods-turn2`、`fullmods-turn3`、`fullmods-turn4`，各含快照、实际UI节点、核对结果和截图。入口与动作日志分别为 `start_saved.py` / `start-saved.log`、`exercise.py` / `exercise.log`。

当前1.25.12修复候选在这套组合下没有复现反馈中的费用消失、寄生无法操作或结束回合卡死。该结论不等于复现并锁定了玩家旧包的完整卡死根因，也不覆盖原玩家未知存档或真正联机。

## 测试输入与边界

首次启动受皮肤模组提示拦截，且原桥接同帧鼠标事件无法稳定操作多模组菜单。没有把这些测试输入失败算作战斗缺陷。独立测试目录的桥接副本增加了跨帧鼠标事件、实际鼠标位置更新；菜单使用原版公开的 DebugPress / DebugRelease 与焦点信号，寄生出牌和杂技选择使用鼠标事件。用户游戏里的桥接DLL未被替换，业务DLL保持不变。

测试局来自此前由原版创建的独立猎人A10存档；通过原版命令进入第二章与指定遭遇，并加入测试卡。为了观察四轮结算，使用过原版加格挡命令。它是机制和界面回归，不是平衡通关测试；控制台跳战也不能替代正常战斗存档重载验证。

本轮使用与真实客户端相同的17个模组运行文件，但以独立本地模组目录加载，未进行Steam联机；几项无明确优先级的皮肤／开场遗物的加载顺序与工坊路径排序有所不同。原客户端与测试客户端的所有影响手牌流程的模组加载顺序一致。

原版客户端现有三个存档的 `progress.save` 与 `current_run.save` 六个文件在测试前后哈希一致。其他模组的启动警告单独留在日志中，本次已完成的战斗交互没有因此卡住。
