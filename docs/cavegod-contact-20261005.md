# Cave God 站位与拳掌接触

整队玩家站位在原来的基础上再下移 60 个场景像素，`AllyContainer` 的累计偏移从 60 改为 120。保留原版多人队形、前后排及随从相对位置；重复对齐不会叠加偏移。抓取释放仍返回各角色原站位。

拳击、双拳、双掌、左右手掌攻击、虚弱攻击、抓取与下砸在接触阶段按实际存活玩家的位置校准。双手攻击分别覆盖队形两侧，单手攻击根据队形宽度调整覆盖范围；蓄力和回收仍使用原动作曲线。两套前后景骨骼采用相同修正，保持手臂与身体的遮挡关系。

骨骼从 27 根增加为 29 根，追加两个手腕方向控制骨；原有加权网格骨骼索引不变。出击手臂使用 IK，手腕世界朝向按原动作以 120 Hz 采样，避免改变瞄准点时手掌翻转。非出击手臂保持原时间线。伤害数值、行动顺序、打击事件时间不变；快速／即时模式会先提交对应接触姿态，再结算伤害。

动画开始事件使用 Variant 接收未使用的借用参数，避免产生由 GC 线程回收的临时 SpineTrackEntry。每帧共用一次受控轨道读取，结束清理时不再从已离树的骨骼创建轨道包装对象。检查工具中的临时轨道引用也改为在调用线程释放。

## 验证

- 原生 Godot/Spine 接触检查覆盖 1、2、3、4 人队形，铁甲战士、静默猎手、储君和故障机器人组合，普通与愤怒形态共 120 组接触采样，全部通过。查看了单人拳击／掌击和四人双掌／单手覆盖的实际渲染。
- 原有动作回归、左右抓取到下砸的衔接、非出击手臂连续性、普通／快速／即时速度下的伤害帧，以及抓牌闭合时序检查通过。
- Cave God 原版界面与完整战斗行为检查通过，包含手臂目标位置、抓取释放、阶段转换和结束清理。
- 29 骨骼、34 插槽、33 个加权网格通过结构检查。原文件超过 MCP 的 32 MB 文本上限，结构检查使用内容完全相同的紧凑 JSON 副本。
- 连续预览为独立 Godot 原生渲染，212 帧、20 fps、10.6 秒；不是实机录像。多人覆盖为原生本地队形检查，没有进行多机联机实战。

输出位于 `build/cavegod_contact/`。预览为 `delivery-preview/cave-god-contact.mp4` 和 `delivery-preview/contact-sheet.jpg`；完整接触数据位于 `review-check/contact-measurements.json`，骨骼结构结果位于 `rig-audit.json`。

## 重建

原动画基准保存在 `source_assets/monsters/cave_god_motion/contact_base.spjson`。运行 `node scripts/build_cavegod_contact.mjs` 生成骨骼和 `CaveGodContactProfiles.cs`，随后执行 Godot 导入／导出。修改基础动作时应先更新该基准，不能把已经含有接触控制骨的输出再次作为基准。

运行 `scripts/test-cavegod-actions.ps1 -ContactReview` 检查接触；加 `-SmoothPreview` 生成连续帧。原动作检查不传这两个开关，抓牌检查使用 `-CardSnatch`。这些入口支持显式传入 `-ImplementationDll` 和 `-PackagePck`，输出通过 `-OutputDirectory` 指定。

交付合并当前工程其他更新，使用独立目录编译统一入口，避免改写其他工作的中间产物。
