# Steam 正式 v0.107.1 启动修复

2026-10-06，模组版本保持 **1.25.0**，工坊条目 **3747607944**。

## 根因

玩家切换至 Steam 正式 `v0.107.1`（commit `59260271`）后，原版 DevConsole 和 BaseLib 扫描模组类型时抛出 `ReflectionTypeLoadException`：`STS2_Things.Acts.Depths` 未实现抽象方法 `get_Index`。

此前标为 107 的本地参考程序集不属于这次 Steam 正式构建。它的 `ActModel` 不含 `Index`、`IsDefault`、`IsUnlocked` 三个抽象接口，导致旧的 107 条件分支与正式客户端不兼容。第一轮涅奥热修复的「107 检查通过」结论因此不能作为正式 107 兼容证据；已在原报告前追加更正。

- 正式 Steam 107 DLL SHA256：`A1F9E653F1E28E4076558FEE1E60D218619CB7E057B887C6417F62C62C6D7A52`。
- 已弃用缓存 SHA256：`C3F825FBB9DD60FDEF896105150B31D2B38AE280F66222B955D771748DCE4626`。
- 旧缓存保留在 `build/v107-startup-fix/rejected-reference/`；现有 107 引用目录已替换为正式文件，并记录 `reference-provenance.json`。

## 修改

- `Depths` 在两版中均正确 override 原生章节序号、默认章节标记、解锁判断。
- 章节目录按原生 `Index` 分组并保留默认章节顺序；删除 107 的额外第二章重抽补丁。正式 107 已有原生 `ActsByIndex` 抽选流程，不应重复抽选。
- 章节探针在 107 中也验证原生章节分组和默认路线。测试工程仅在目标依赖存在时复制 `Sentry.Godot.dll`，适配正式 107 的依赖布局。
- 统一启动探针支持独立日志路径。保留上一轮涅奥过滤内部横路规则的修复。
- 版本、PCK、美术和 BaseLibBridge 字节保持不变。

## 红绿验证

全部证据位于 `build/v107-startup-fix/`。

1. `user-crash.log` 保存用户启动日志。`startup-before.log` 使用当前正式 107 的 DLL、依赖及 PCK，只加载此前发布的本模组，即可复现同一 `get_Index` 启动崩溃。
2. 修复后，两版 Release 重建零警告、零错误；统一包目标识别、145 个模组模型集合和内嵌实现哈希检查通过。
3. `startup-after-v107.1.log`：正式 107 的原生 ModManager 加载发布目录、初始化模型、预加载及 JIT 成功，涅奥选项数为 3。
4. `config-v107.1.log`：44 组涅奥回归及完整配置探针通过，涵盖 1/4 玩家、遗物开关、真实自定义规则、横路存档恢复与多人配置协议。此处多人为原生代码探针，并非多台客户端实测。
5. `depths/probe-v107.1.stdout.log`：7312 项断言通过，包括章节池、原生章节初始化、保存/读取、资源和强怪战斗检查。
6. 真实 Steam 107 可执行文件使用独立离线身份 `125009`，加载本模组与测试桥：主菜单成功；普通战士新局的涅奥三个选项可见；领取奖励后进入地图。种子 `HJEVH554FT` 由原生流程生成 `OVERGROWTH → DEPTHS → GLORY`。
7. 用原版 `room Boss` / `kill all` 缩短第一章战斗，随后点击原生奖励界面的前进按钮，实际进入 `ACT.DEPTHS`、`CurrentActIndex=1`，石板地图正常渲染。未使用 `act` 命令或修改已生成章节。记录为 `live-evidence.json`、`live-v107.1.log`、三个截图及独立测试存档。

测试使用独立存档，未改写用户 Steam 身份的进度或游戏局。测试进程已关闭。最终实机日志没有原先的反射/接口异常；有一条原版 Sentry 在离线关闭上报时的 SDK 关闭提示，未阻止启动或换章。第一次测试复用了新版本按键设置，产生 InputMap 提示；随后仅为独立身份恢复原生 107 默认按键并重新启动，最终日志不含该提示。
