# 晶片悬浮／抽牌卡住反馈：实机排查

用户反馈晶壳蜗牛破壳后生成的晶片停在屏幕中间，后续无法抽牌。当前工作区和安装包为 1.25.10，本轮尚未定位该反馈的根因，未修改生产逻辑。

## 本次实际执行

- v0.111.0：独立离线身份 125032，原生蜗牛三人组。实际打击打碎晶壳，晶片进入弃牌堆，等待后正常抽到手牌。
- v0.111.0：用原生腐化清理测试用防御牌，让抽牌堆与弃牌堆为空，再打出原生剑柄打击，打碎晶壳并立即洗回、抽取唯一的晶片。六秒后手牌模型与 NCard 均为 9，预览／特效容器残留卡牌为 0，第二回合正常开始。
- 用户切换到真正 Steam v0.107.1（59260271）后，关闭自建的 v111 测试进程，重新启动独立身份 125033。使用原先原生 107 的测试设置；第一次复用了 111 按键设置，出现不存在的 controller action 诊断，已经换成 107 设置重开，没有把该次混合设置当作验证证据。
- v0.107.1：相同剑柄打击即时抽晶片流程通过，模型／界面 9 张、残留 0，第二回合正常开始。
- v0.107.1：补测最后一只晶壳蜗牛被致死攻击同时破壳；没有残留晶片预览，随后另起一场原生蜗牛遭遇，第一回合为 5 张模型和 5 个可见卡牌节点，Phase=Play。此流程日志没有 ERROR 或 Exception。

测试只加载本模组和 MCP 桥，没有覆盖反馈玩家的其他模组组合。腐化／额外能量／力量和击杀其他敌人仅用于隔离回归，不是生产规则修改。Steam 存档未改动。

## 接下来需要的证据

两版上述流程没有复现用户症状，不能据此宣称已修复。需要反馈玩家的具体模组版本、发生问题的攻击／抽牌效果、其他模组，以及问题发生后的日志或可复现存档。

原版 Noisebot／SoulFysh 也采用 `AddGeneratedCardToCombat` 后 `PreviewCardPileAdd`，因此不能仅因晶片出现预览，就把这段流程判为错误并盲目删除。

证据目录：`build/snail-chip-fix-20261008/`，含动作、快照、节点列表及两版日志。`before-v107-immediate/` 和 `before-v107-lethal-2/` 为通过记录。初次脚本超出 scene 工具的 600 节点上限，以及 kill 命令索引错误，均已纠正，未作为游戏 bug 证据。
