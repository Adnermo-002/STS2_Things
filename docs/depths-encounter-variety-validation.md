# 深处强怪池 1.25.0 验证记录

2026-10-06 完成。本轮针对强怪池扩充及其相关怪物、卡牌、场景和存档交互进行了编译、原生自动化与单人实机验证。发现并修复三处内容问题，修复后的同版本包已覆盖安装。项目、统一入口、双版本清单、发布包和游戏安装均保持 **1.25.0**。

## 修复结果

| 问题 | 复现证据 | 修复与复验 |
| --- | --- | --- |
| 新阵容的增益图标被手牌或结束回合按钮挡住 | 原实机采样中，海绵图标约 64.7% 被手牌覆盖，最右蜗牛图标约 26.5% 与按钮重叠；修复前几何检查失败 | 六组新阵容的敌方槽位上移 64 个场景像素，保留相互位置。九次普通／满手牌实机采样共检查 21 个图标，全部通过；玩家站位与数值不变 |
| 海绵喷水在极短起始帧出现多边形三角化错误 | 实机日志与生产绘制探针均复现 `Invalid polygon data, triangulation failed` | 将细长的 58 顶点轮廓按同一边界画成凸四边形带，并跳过不足半像素的收缩帧。每个游戏版本覆盖 252 个绘制姿态，修后实机喷水正常 |
| 复用潮墓蛞蝓死亡音效的怪物没有正确播放声音 | 实机报 `cannot find sfx path: .../gravetide_slug_die`；修前路由检查失败 | 对本模组中复用已注册音效路径的怪物使用原生音频播放器。水蛭、海绵、洞胃、逆流蝾螈和潮墓蛞蝓通过回归，灯笼鱼的原版 FMOD 路径仍保留 |

安装核对另发现 Workbench 安装器只复制清单、DLL、PCK，遗漏包内可选的 `STS2_Things.BaseLibBridge.dll`。游戏关闭后已从同一发布包补齐；四个安装文件、暂存文件及 ZIP 内文件的 SHA256 全部一致。

合计 **288 场原生战斗用例、2,304 轮敌方行动周期、22,041 次断言检查**。这不是 288 次人工通关。自动化使用真实游戏模型、抽牌与回合 Hook、怪物行动和伤害命令；为跑完状态机，测试角色提高了生命，结尾用致死伤害验证战斗可结束。

人面柱原本固定种子的样本只选中了爬岩蜗牛，因此额外扫描原生种子，覆盖爬岩蜗牛、晶壳蜗牛、水蛭、灯笼鱼、垂丝蛾和海绵全部六种伙伴；每种均验证了完整循环、槽位、补层后击杀与临时卡牌隔离。

回归重点包括：

- 十二个独立强池条目可达，沿用原版等权不放回队列；地图生成和存档恢复保留完整队列；第二章与原版巢穴并列，章节推进不替换原版逻辑。
- 涎丝蜗牛修壳、无目标时即时改意图；晶壳破壳后停止缩壳并向每名玩家奖励晶片；爬岩破壳推迟碾压。
- 洞胃对每名玩家生成两张带保留的原版碎屑，并在吞噬回合正确消耗；临时保留不污染原型或永久牌库。
- 致盲费用变化、抽牌与重抽、回合结束恢复、特殊费用、满手牌与多人归属。
- 海绵按生命损失比例蓄水、多段伤害与格挡边界、喷水重置和回血；冲净、寄生牌清除后插入动作、眩晕与死亡处理。
- 延迟捆绑在下回合抽牌后触发，解缚、自动出牌限制、弃置／消耗／死亡清理和多人隔离；费用保持原值。

最终双版本综合探针、伙伴专项探针的 stderr 均为空。双版本实现、统一入口与可选 BaseLib 桥接编译均为零警告、零错误；Godot 导入和导出成功，源码静态审计通过。

## 实机与视觉

使用正式 v0.111.0 游戏与安装后的修复包，在独立离线身份 `125006` 中测试；没有操作用户的 Steam 存档。六组新遭遇均进入实际战斗并结算：

| 遭遇 | 实机观察 |
| --- | --- |
| 潭边生灵 | 破晶壳、获得和打出晶片，海绵蓄水／喷水／回血，致盲与恢复 |
| 蛾与蜗牛 | 下一回合捆绑、丝线外观、回合清理、修壳与破壳推迟碾压 |
| 洞胃与蜗牛 | 两张保留碎屑、吞噬、力量增长、攻击循环 |
| 浸水石壳 | 修后实际打击填满蓄水并触发喷水；三个敌方回合与蜗牛碾压正常 |
| 灯下飞蛾 | 修后指定牌打出后另一张解缚；花屏、乱码、随机费用与恢复正常 |
| 洞胃与灯鱼 | 修后首轮四个敌方回合完整运行，投食／吞食与致盲同场工作 |

实际领取过金币与卡牌奖励，并返回可操作的深处地图；重新启动后，章节、金币、所选卡牌及已保存进度保留。调试 `fight` 不属于实际地图节点，因此本次实机读档回到已保存地图；不将其描述为“战斗中每个瞬间都原样恢复”。

另外生成并人工查看六组新阵容各一张单人、一张四人原生渲染图，共十二张。修复后实机还检查了九次静止手牌布局，包括满手十张；被悬停放大或拖动的卡牌不属于该遮挡检查的输入。

## 日志中保留的诊断

修复后实机战斗阶段未再出现喷水三角化错误、死亡音效缺失或运行异常。保存回主菜单时出现一次 Godot `Invalid Task ID`，位置为 `worker_thread_pool.cpp:418`。另开独立身份 `125007`，**禁用 STS2_Things、仅保留 Workbench 测试桥接**，主菜单后台预加载也复现了相同信息，随后预加载正常完成。证据可排除这次内容更新是该消息出现的必要条件；未对引擎或原版预加载流程加补丁。

退出进程时的少量 RID／ObjectDB／资源未释放日志也保留在原始记录中。此前完全没有加载模组的启动基线中同样存在此类退出诊断。没有把“战斗错误已消除”写成“所有日志绝对干净”。两个实机测试进程均已正常退出。

## 结论与边界

本次更新涉及的强遭遇及相关交互，在上述范围内通过验证，发现的三处内容问题已修复并复测。没有进行双机真实联机、完整新开局平衡通关或所有第三方模组组合穷举；多人结果来自同进程的原生多人模型，不能替代网络同步实测。有限测试不能证明绝对零 bug。

已生成的旧存档队列不会因更新重排。由于按要求保持 1.25.0 不变，联机各端应使用本轮相同的修复包；仅比较版本字符串不能区分先前的 1.25.0 包。
