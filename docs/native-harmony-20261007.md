# 原生接口迁移与人面柱视觉修复 — 1.25.6

> 后续全模组复查更正：v111 的商人价格 getter 实际调用 `ModifyMerchantPrice`，107 也有相应模型 Hook。价格覆盖可评估迁移，购买前猜拳拦截仍是单独职责。见 [全模组原版复用审查](native-implementation-review-20261007.md)。本页其余已实施迁移与测试是当时的历史记录。

本次将四项可以由原版承担的功能迁回原生入口，并修复 v0.107.1 的无效 Spine 轨道对象。统一包保留此前的人面柱数值／坍落规则、涅奥恢复修复及 1.25.5 深处事件池更新。没有改动怪物原画、背景或已确认的玩法。

## 实际迁移

| 原补丁 | 原生实现 | 验证 |
| --- | --- | --- |
| `CaveGodPortraitCompatibility`：全局覆盖 `CardModel.HasPortrait` | 使用原版 `PortraitPngPath` 的模型名命名卡面，五张牌通过原版 `HasPortrait`、`PortraitPath` 加载。三个新增文件是原画的字节副本，制作脚本同步输出这些名称 | 五张卡面路径、存在性及纹理尺寸验证 |

| `BorrowedEmberRestOptionsPatch`：全局补丁 `RestSiteOption.Generate` | 通过 `ModHelper.SubscribeForRunStateHooks` 注册 `SpentEmberRestPolicy.TryModifyRestSiteOptions`。原版遗物选项处理后才执行熄火规则 | 1／4 人下覆盖铲子、Mend，保留其他玩家选项，休息房间正常结束 |

新增的 `SpentEmberRestPolicy` 是原版模型，未向存档强加额外的 Modifier 实例；其生命周期由原版订阅者机制管理。当前两个目标版本均发现 150 个模型。

## 人面柱：已确认的问题与尚未复现的反馈

玩家反馈是第四回合手牌不显示，单人／联机及版本未知。本次用独立测试身份 `125020` 在真实 v0.107.1 游戏进入深处和弱池人面柱，逐回合检查牌堆模型、手牌节点与截图：第一至第五回合均为 5 张模型和 5 个可见卡牌节点，未复现该反馈。

不过，此次实机确定复现了人面柱视觉每帧抛出 `NullReferenceException`。v0.107.1 的 `MegaAnimationState.GetCurrent(1)` 在空轨道返回非空包装对象，但其 `BoundObject` 为 null。`NHumanFaceColumnVisuals._Process` 随后调用 `GetTrackTime`，导致旋转及储备层初始化失败并持续刷日志。v0.111.0 原版已经过滤这种空原生对象。

修复在 `Sts2VersionCompatibility.TrackEntryScope`：先检查原生对象不为空且 `GodotObject.IsInstanceValid`，无效时视为没有轨道，交给既有逻辑创建真实旋转轨道。没有增加 Harmony。

回归使用生产视觉场景和真实 Spine 绑定：旧 DLL 在两帧后报告 `wrapper=True,native=False` 并失败；新 DLL 能启动三个交替旋转轨道、绘制三个储备层，并执行四次行动，10 项断言通过且无引擎异常。此结果证明空轨道异常已经修复，**不证明未知玩家环境中的手牌消失已经定位**。

最终 1.25.6 在真实 v0.111.0 游戏、独立身份 `125020` 又验证了强池人面柱搭配吸水海绵：第一至第五玩家回合均为 5 张模型、5 个可见 `NCard`，第四回合截图人工复核正常。该测试每回合用原版 `block` 命令保护玩家，仅验证 UI 和生命周期，不验证胜率。未保护的空过测试在第四个敌方回合生命归零并按原版规则清空手牌，这不是对未知玩家反馈的归因。

此次真实 V111 控制台换章中还出现两条 Godot `Invalid Task ID` 诊断，后续五回合没有增加，未观察到手牌缺失；保留 stderr 作为验证限制。没有把实机日志宣称为完全无引擎诊断。完整离线探针的 stderr 检查通过。

证据在 `build/column_hand_20261007/`：逐回合手牌报告与截图、失败和通过的轨道测试，以及经完整 SHA256／长度校验的 `baseline-game.log.gz`。重复日志原文件约 6 GB，压缩保留完整内容，校验见 `baseline-log-integrity.json`。

## 保留 Harmony 的接口依据

这是一次有行为证据的迁移，不以删除数量代替兼容性。声明清单见 [补丁清单](harmony-inventory-20261007.md)，同时包括运行时手动安装的补丁及统一引导层的说明。清单是源码声明数，不代表每个版本实际启用的目标方法数；条件编译、单类多目标和手动补丁会影响数量。

| 功能 | 保留理由 |
| --- | --- |
| 章节、原版章节的事件／遭遇／Boss 注册 | `ModHelper.AddModelToPool` 面向卡牌／遗物／药水等模型池，没有章节和事件注册入口。`ModelDb.Acts` 及原版章节目录显式枚举，模型自动发现不会自动加入这些目录 |
| 深处仅模组事件 | `Depths.AllEvents` 已用原生覆写；但非虚的 `GenerateRooms` 仍追加原版共享事件，旧保存池也须在下一次抽取时处理。仅对深处调用原版 `RemoveEventFromSet` 的两个补丁由 1.25.5 延续 |
| 遭遇权重、强制 Boss、第二 Boss | 池覆写能控制成员，不能表达已有的配置权重／强制选择和旧存档再生成政策；原版对应抽取过程没有通用权重 Hook |
| 模型池稳定排序 | V111 `ModHelper.ConcatModelsFromMods` 仍直接拼接，没有排序。为多人保持池顺序一致的三个窄补丁继续保留 |
| WAV 音乐／音效路由 | 原版音频命令使用 FMOD 事件，不能直接播放模组 `res://` WAV。本次只将资源预载迁回原生，播放路由仍负责本地 WAV 和原版 FMOD 回退 |
| 音频退出清理 | `AfterCombatEnd` 是战斗模型事件，不等同于节点退出。退出、重载及中止也要释放本地循环播放器，故仍在 `NCombatRoom._ExitTree` 清理 |
| 联机配置和可选设置库加载 | 房主配置必须在原版开始／恢复消息和随机生成前锁定，普通回合 Hook 太晚；全部模组加载完成的公开事件缺失，可选库延后加载仍需 `ModManager.State` 重试 |
| 分裂附魔的永久成长、升级、降级与读档 | 原版附魔修改战斗输出不能拦截各张原版成长牌的直接数值／费用 setter，也不能完整还原永久未分裂值。相关拦截仅对持有本附魔的牌生效 |
| 弃牌堆优先抽牌 | `ModifyHandDraw` 只能改变抽牌数量，`AfterCardDrawn` 已发生在原版取牌之后；两者都不能改变抽牌来源 |
| 致盲视觉清理／复制 | 临时费用已用原版 `SetThisTurn`；补丁仅同步包装视觉元数据到复制牌，并与每张牌的原生回合清理及 `NCard` 重建时机对齐 |
| 横路历史／地图／免费旅行 | 原版默认每行一个历史记录，免费旅行按下一行返回。横向重复同行房间须保留存档历史映射、地图按钮和旅行兼容；一般地图生成 Hook 不覆盖这些读取入口 |
| 蜗牛意图计数、专属站位 | 原版 `NIntent.UpdateVisuals` 只为攻击／状态牌意图显示数字；Encounter 没有单独玩家队形偏移接口，保留目标明确的 UI 补丁 |
| 始源眼复苏／雾菇强制眩晕 | 原版能力调用 `SetMoveImmediate` 时未强制越过既有的一次性状态；仅为这两个自定义模型的指定状态修正强制转换 |
| 墓潮随从的 Ravenous | 原版能力将怪物强转为 `CorpseSlug`，自定义随从另有尸体替换规则；窄补丁维持原版能力名称、层数和动作结算 |
| 商人猜拳及控制台事件重入 | 购买前 wrapper 拦截及商人房间资源目录仍缺等价模型入口；价格覆盖已有 `ModifyMerchantPrice` 可评估迁移，见后续复查。控制台重入需在换房前清屏并阻止替换等待选择的实例 |
| V107 统一包归属 | V107 加载器只保存单程序集，需两个引导补丁使内嵌实现参与模型及序列化发现；V111 已使用官方 `AssociateAssemblyWithMod`，未添加同等补丁 |
