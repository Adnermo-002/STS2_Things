# CaveGod 由核心统一推进回合

状态：Accepted，2026-09-19。用户授权大幅重构，以原版 API 和更可靠的 Boss 行为为优先。

旧实现让核心与双臂分别维护四回合循环、各自记录中断点，再在苏醒时尝试对齐。破爪后的核心补偿攻击没有攻击意图，核心部分招式又使用手臂作为伤害来源，导致玩家看到的意图与实际结算脱节。

核心现在拥有唯一的原版 `MonsterMoveStateMachine`，使用 `MoveState` 和 `ConditionalBranchState` 描述两个四回合循环、三回合核心暴露与转阶段。双臂通过同一抽象模型投影核心的下一招，保留原有具体类名、ModelId 与资源路径。回合初发布意图，行动时不会用未经预告的另一招替补；玩家击破石爪后获得完整的取消重摔收益。

核心保留一个中断位置。取消抓取后，已失效的重摔直接跳到下一招；因敌方回合的中毒或反伤进入暴露期时，仍保留三次完整玩家行动窗口。恢复与转阶段由位于最后槽位的核心负责，双臂不能提前互相唤醒。原生眩晕仍可替换手臂行动。

以 v0.111.0 的帝王蟹、知识恶魔为成长参照，每个四招循环最后一招完成后，核心与双臂各获得 2 力量，DeadlyEnemies 进阶为 3。成长由带 BuffIntent 的招式执行，跨阶段保留。第三回合苏醒也按同档增加一次力量，显示治疗与强化意图，防止反复断臂无限冻结成长；受击中断本身不会立即增加力量。双臂交替担当普通循环的主攻手。未照搬帝王蟹死亡时的 +6 力量和 99 格挡，因为本 Boss 的断臂是可重复触发的暴露机制。

原版 `CanReceivePowers` 依赖可受击判定；因此核心只在自身力量命令期间临时开放接收效果。不可选取和伤害归零规则始终保留。手臂清理负面状态使用 `TypeForCurrentAmount`，而不是只看类型声明，确保负力量也会移除。所有清理、回血、伤害和成长均走原版 Commands。

本次只构建并验证 v111；遵守仓库统一版本约束，活动 manifest 与程序集版本统一升至 1.10.1；本次产出的 v111 包标记为 1.10.1，防止新旧玩法版本通过联机版本匹配。未改变既有 ModelId、存档字段或 PCK。真实网络联机与玩家实战手感仍需后续验证。

> 2026-09-29 补记（不改动上文决策记录）：显示名统一为「活体巨岩 / Living Megalith」。成长节奏已由「每个四招循环末尾」改为「晶脉满 4 层后的晶簇崩发」，磐石守势与狂暴崩山不再附带成长；苏醒成长保留，但崩落裂痕贯通时取消。手臂 MoveState id 改为与本地化键一致的 UPPER_SNAKE 形式（`ThingsCaveGodHand.MoveId`）。详见 `docs/cavegod-review-20260929.md` 与 `design/balance/balance-check-cavegod-2026-09-19.md` 的补记。
