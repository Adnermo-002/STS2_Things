# v0.111.0 开场寄生与手牌界面调查

玩家反馈「馋嘴洞胃＋垂丝蛾＋吸血血蛭」开场费用消失、寄生无法打出或弃掉、杂技选牌与结束回合卡住。截图为 beta v0.111.0；初次调查时其他五个模组、模组版本和种子未知。本文记录首轮 Things＋MCP Bridge 验证。用户后来安装了反馈玩家同组模组，17模组的实机复测已通过，见 [后续复测记录](parasite-hand-multimod-20261008.md)；仍不把已确认的顺序修复等同于完整旧包卡死根因已经锁定。

## 已确认缺陷与修复

旧水蛭在 `BeforeCombatStart` 用 `CardPileCmd.Add(skipVisuals: true)` 把寄生放进模型手牌，在 `BeforeHandDraw` 手工创建 `NCard` 并补 `NHandCardHolder`。原版工具箱在同一抽牌前阶段先生成自己的手牌，导致两种顺序分离：

- 模型：寄生、计策、普通起手牌。
- 界面：计策、寄生、普通起手牌。

实机只读回归脚本在修复前确实失败。`ForceRefreshCardIndices` 只刷新布局，不能补全生成／移堆通知或把顺序重新对齐。

现在 `BeforeCombatStart` 只应用水蛭原有的隐藏能力；每只水蛭在第一玩家回合的 `BeforeHandDraw` 通过原版 `CardPileCmd.AddGeneratedCardToCombat` 给每名存活玩家一张寄生。参考两个支持版本的 `Toolbox.BeforeHandDraw` 与 `CombatManager.SetupPlayerTurn`，由原版统一处理模型、可见节点、牌堆通知、索引、溢出及抽牌。没有新增 Harmony。

保留每只水蛭开场一张、直接进手、1费消耗、无固有、正常抽牌不减少（仍受原版满手上限限制）、回合末喂养、消耗后下一回合插入补牌等机制。每个 mutable 水蛭拥有独立的玩家集合，同一首回合 Hook 重入不会重复生成。测试夹具也补齐真实的抽牌前 Hook，避免继续依赖旧的提前静默塞牌。

实机回归入口：

```powershell
python -X utf8 scripts/test-parasite-hand-live.py --launch build/parasite-hand-beta-20261008/candidate-launch.json --out build/parasite-hand-beta-20261008/green-toolbox
```
