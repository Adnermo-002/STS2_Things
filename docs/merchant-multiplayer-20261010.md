# 商人猜拳版本兼容与多人交易验证

2026-10-10。玩家反馈多人猜拳无法触发，游戏版本未知。先完成 Workbench 双版本运行库，再使用两份完整原版客户端检查相同触发条件。

## 已定位并修复

已发布 1.25.13 的商人六个源码文件全部受 `STS2_V111` 包围；107.1 构件没有编入功能，单人或多人都无法触发。实际两版单人客户端将金币设置为比商品价格少 10，点击同一商品五次：107.1 未显示猜拳，111 显示。修复后同一原生操作在两版均显示猜拳，并正常结束、解除输入阻塞、关闭与重开商店；同店五次再点不会重开已消耗的猜拳。

移除整个功能的版本排除，仅在 RNG 构造处保留真实接口适配：107.1 使用 32 位种子，折叠既有 64 位组合的高低位；111 沿用原随机流。保持原规则：缺口最多 20、同一商品第五次合格购买点击触发，每个玩家每间商店一次。没有增加 Harmony 补丁数量，继续由原生购买流程结算库存、遗物、金币、购买 Hook 和同步消息。

这证明并修复了一个明确的版本缺口；没有玩家原日志／版本信息，不能据此断言所有多人反馈均源于此。

## 验证

- 对实际 107.1／59260271 与 111／41cef1ea 两套程序集分别编译，零警告／错误；统一引导在两版分别加载 155 个模型，内嵌实现哈希一致。
- 原生购买回归各 212 项：1–4 名玩家、房主与客户端身份、本地 UI 库存和离屏库存的隔离、前四次正常失败／第五次触发、赢后花费与原生遗物奖励、一次金币及奖励同步消息、其他玩家不变、输后无损耗与同店不可重开、价格恢复、确定性随机流及商店 RNG 不被消耗。
- 该回归只替换图形猜拳段；购买入口、生产计数／议价逻辑、原生命令和 RewardSynchronizer 均实际运行。网络端点记录原生消息，没有宣称它是实际 LAN 连接。
- 两份完整客户端的单人图形流程均实测，使用按实例绑定的 Workbench 1.2.1；没有操作玩家窗口或修改其存档。真实联网多人尚未实测。

探针入口为 `scripts/test-merchant-bargain.ps1 -TargetVersion v107.1|v111 -DataDir ... -RuntimeDependencyDir ... -ImplementationDll ... -OutputDir ...`；源码位于 `tools/MerchantBargainProbe/`。原生资料在 `build/merchant-multiplayer-20261010/`，实机资料在 `STS2-MCP/.state/dual-version-107-20261010/`。
