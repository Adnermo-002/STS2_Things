# 深处：吸血血蛭

> 数值已在 1.25.2 按原版第二章提高；本文原始设计数值保留为制作记录，当前完整数值与验证见 [深处数值校准](../docs/depths-balance-20261006.md)。

按最终要求：弱怪池 **2 只**、强怪池 **3 只**，与已有灯笼鱼共享深处的普通战池。血蛭使用独立的根菌洞穴背景引用，灯笼鱼继续使用河湾，火堆场景不受影响。

## 寄生

`LEECH_PARASITE`：1 费状态牌，**消耗**（无固有），不可升级。打出即清除。

每只血蛭在战斗开始时，直接向每名存活玩家的手牌生成一张寄生，弱战 2 张、强战 3 张；随后照常抽取 5 张起手牌。寄生不占用正常起手抽牌的数量，不加入永久牌组。所有塞牌行动也直接加入手牌；手牌已满时依原版规则进入弃牌堆。直接生成不是抽牌，不消耗冲净层数。

每张寄生在其拥有者回合结束时仍在手牌，便让所有存活的吸血血蛭各获得 **2 再生、2 力量**。多张分别结算；提前打出、丢弃或消耗能阻止该张结算；其他敌人和死去的血蛭不受影响。

1.13.4：寄生被打出消耗、被海绵冲净或被其他效果消耗时，所有存活血蛭只记录补牌请求，保持本回合已经展示的意图。当前行动执行后，在敌方回合结束时将下一回合意图设为「再寄生」，各向玩家手牌塞 1 张寄生。再寄生是插入回合：记住每只血蛭原本下一步的行动，结束后继续该行动，既不推进也不重置正常循环。普通弃牌与回合末弃牌不触发；同一回合多张寄生被消耗合并为一次补牌。当前攻击、防御、普通寄生或眩晕均先完成；若在再寄生回合又消耗了寄生，则下一回合继续插入再寄生，并保留同一个原行动续接点。

响应仍通过原生「顽固寄生」Power 的消耗钩子处理，但按原版隐藏能力方式设置 IsVisibleInternal=false，不显示 buff 图标、提示或闪光。寄生卡面只描述留手惩罚。冲净消耗下一张抽到的状态牌；仅消耗寄生会触发血蛭反应。

使用原版 `RegenPower` 和 `StrengthPower`、原版图标与回合处理。再生在血蛭方回合结束时恢复当前层数的生命，随后减一。再生首次施加的原版多人倍率已抵消，避免同一张牌第一次给予超过两层；后续原版 Power 钩子仍正常处理。

## 数值与行动

| 项目 | 普通进阶 | 对应高进阶 |
|---|---|---|
| 生命 | 26–30 | 30–34（坚韧敌人） |
| 啜血／再啜 | 4 伤害 | 5 伤害（致命敌人） |
| 吸血 | 恢复实际造成的生命伤害 | 同规则 |
| 盘伏 | 6 格挡 | 6 格挡 |
| 寄生行动 | 向目标玩家手牌加入 1 张寄生 | 同规则 |

循环：**啜血 → 寄生 → 再啜 → 盘伏**。

- 弱战起始阶段 `[0, 3]`：第一回合一只攻击、一只盘伏。
- 强战起始阶段 `[0, 1, 3]`：第一回合分别攻击、寄生、盘伏。
- 完全格挡阻止吸血；不把格挡伤害、过量伤害计算为回血；反伤杀死血蛭时不会通过回血复活。
- 寄生消耗能量，忽略它则使群体逐渐成长；优先击杀一只可减少后续伤害和受益目标。击杀全部血蛭后寄生的留手惩罚失效。

## 外观与原生骨骼

设计参考原版尸蛞蝓和绒毛蠕虫的手绘色块、吸盘口造型与卡通比例。新角色为暗砖红色、短胖分节身体、卷尾、大小不齐的半闭眼和两颗钝齿；避免写实湿润皮肤、血液和恐怖尖牙。

原创角色和状态牌插画通过用户此前指定的接口、imagegen 官方 CLI、`gpt-image-2/high` 生成。提示词保存在 `source_assets/monsters/sanguine_leech/`。原版图像只作风格参考，游戏运行不使用原版怪物贴图替代血蛭。

原画只进行透明边缘处理和去除低透明度装饰光晕，保留绘画颜色。人物为连续加权网格：17 骨骼、3,124 顶点、5,902 三角形。颈部蠕动、吸盘口、上下唇、双眼、腹部和卷尾独立绑定。

10 组动作：待机 `idle_loop`、吸血 `attack`、播种 `cast`、盘伏 `curl`、吞咽 `feed`、受击 `hurt`、死亡 `die`、复起 `revive`、入场 `summon`、强化 `power_up`。
攻击接触 0.46 秒、寄生释放 0.62 秒、盘伏 0.38 秒；代码和 Spine 事件对应。待机闭环，死亡末帧与复起首帧连续。接触阴影跟随原生角色节点。

## 自审与验证

- 第一轮检查发现原画有多余的透明光晕，最终资产已清除；在深色底和真实洞穴中查看边缘。
- 卷曲动作最初让眼下的少量三角形翻折，修正头部权重后用官方 Spine 4.2.43 重新采样全部 881 帧：零翻折，闭环与死亡／复起误差均为零。
- 已对照原版素材和实际原生战斗截图审核比例、色块、轮廓、纹理、地面接触和意图／血条可读性。三只编队缩小并留出间距。
- 行为探针覆盖池分类、数量、阶段循环、生命／伤害进阶、开场直接入手与正常抽牌、状态清除、存活目标筛选、多人层数、回血与格挡。
- 通过原生 `CombatManager.DoTurnEnd` 验证手牌筛选、临时移动到出牌区、效果结算与回弃牌堆；回调不会错误地再次检查手牌位置。保留寄生会回弃牌堆，只有实际打出时才消耗。
- 视觉探针实际加载导出的 PCK、原版 `NCreature`／`NCard` 与 Spine 扩展；包含双只／三只遭遇、寄生卡面、留手强化、十组动作和动画序列。

最终记录：v111 与 v107.1 各 105 条血蛭行为断言；深处章节分别 754／753 条；v111 原生视觉 218 条。双版本入口均识别 83 个模组模型，并核对内嵌 DLL 与被测 DLL 的 SHA256。

最终通过数量和对应日志记录于交付目录，不以静态结构检查替代游戏渲染。尚未宣称长局平衡或双机联机已完成人工游玩。

## 重建与测试

先在项目根目录运行 `scripts/prepare_sanguine_leech_assets.py`，然后在 `tools/SanguineLeechRig` 中依次运行：

```powershell
python -m rigkit build
python -m rigkit export
python package.py
node verify.mjs
python package.py --deploy
```

Python 使用已有 `Pillow/numpy/opencv-python` 环境；Spine 验证复用 `tools/ScaleBeetleRig` 锁定的官方运行时。
项目使用原生 Godot 导入与 PCK 导出；运行 `scripts/test-sanguine-leech.ps1 -TargetVersion v111` 或 `v107.1` 验证行为，`-Visual` 验证 v111 渲染。
只有更新生成图片时需要图像 API，普通重建无需密钥。

控制台测试：`fight SANGUINE_LEECH_WEAK` / `fight SANGUINE_LEECH_ENCOUNTER`。进入第二章深处：先 `act 2`，再 `act DEPTHS`。
