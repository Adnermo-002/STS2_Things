# 原版实现复用

用于新增玩法、重构机制或审查自定义流程。单纯文案、贴图或数值修改只核对其相关入口；不为小改动扩大成全模组重构。

## 先找到职责，再选实现

1. **确认版本。** 从当前客户端、项目目标和实际 DLL 定位原版。同一接口在两个支持目标的签名、可见性和行为可能不同；旧解包目录和历史审查仅作线索。
2. **找同类原版。** 沿最相近的卡牌、怪物、能力、遗物、事件或界面，追到它调用的 Cmd／Factory、Hook 分派和资源节点。读完整结算路径，不能只看到一个同名方法就判定可替代。
3. **分开职责。** 列清触发时机、玩家／怪物归属、模型变化、UI 反馈、存档／网络。算法或美术可自定义，牌堆、伤害、奖励等结算优先交给原版。手工创建可见节点不等于执行了原生造牌；接入模型也不等于所有生命周期已被调用。
4. **选择最小扩展。** 优先模型覆写、Cmd、Factory 和已有 Hook；原生只提供 protected helper 时评估明确的兼容适配。没有等价入口时保留窄 Harmony，尽量让原版继续执行其余流程。评估替代方案是否引入更多脆弱接口，而不是只统计删了多少补丁。
5. **验证实际语义。** 说明哪些行为必须保持，再按本轮授权执行相关对照检查。记录入口、同类参考、仍需补丁的缺口及未验证项。用户要求审查时交付结论；实施、安装和发布仍按当轮范围。

## 按机制寻找的入口

| 机制 | 优先查的原版职责 |
| --- | --- |
| 怪物行动与意图 | `MonsterMoveStateMachine`、Move／BranchState、Intent；攻击构建器与原生眩晕，已预告行动和强制转换的规则 |
| Buff 与临时改牌 | `PowerModel`、`AfflictionModel`／`EnchantmentModel`、动态变量和 `PowerCmd`／`CardCmd`；回合费用用原生临时费用接口 |
| 加牌、抽牌、消耗、移除 | `CardPileCmd`／`CardCmd`；区分生成、抽到、永久入牌库和复制，对应 Hook 和 UI 通知不同 |
| 事件与古神奖励 | `EventModel`／`AncientEventModel`、`EventOption`、原版选牌／选遗物命令、奖励工厂和领取／结束历史 |
| 遗物、地图、休息和商人 | `RelicModel` Hook；`ModifyGeneratedMap`、`TryModifyRestSiteOptions`、`ModifyMerchantPrice` 等实际分派入口；无状态策略可由 `ModHelper.SubscribeForRunStateHooks` 订阅 |
| 保存、联机与资源 | `SavedProperty`、原生可序列化卡牌、GameAction／消息协议、模型 `AssetPaths` 和命名路径；核对目标版本的发现／预载流程 |

这是搜索方向，具体签名与可用性每次查当前目标；不能把 Hook 名称当作已经覆盖某条业务调用的证据。

## 必须核对的边界

- **时序与分派。** Hook 是否在该阶段实际枚举该模型，是否早于造手牌／复制牌库，是否已执行原版阻止判断。避免递归重调命令而重复触发，或把下一轮效果移到当前已预告回合。
- **归属与可变性。** canonical 模型只描述原型，运行状态放在 mutable 模型或明确的会话数据。订阅的纯策略不要为保存方便强加为开局 Modifier；真正需要持久保存的状态仍必须走已核实的存档路径。
- **多人与 RNG。** 共享效果、个人牌堆和本地视觉各自归属；先确认原版是否已经缩放。保持种子、抽选顺序、房主配置与所有客户端模型发现一致。
- **生命周期。** 验证选择／取消、移堆／消耗、死亡／逃跑／吞噬、回合／战斗结束、重建节点和读档中与本改动有关的部分。相似方法可能有不同历史、奖励、Hook 或清理副作用。
- **资源与显示。** 包里资源可加载且实际被预载，原生模型变化驱动 UI。特效和骨骼仍满足用户的表现要求，不能为了“原生化”换成不等价的图标或动画。

## 本项目已核实的参考

- **开局造牌：Toolbox。** 两支持目标的第一回合 `BeforeHandDraw` 通过 `CardPileCmd.AddGeneratedCardToCombat` 加手牌；适合评估水蛭手工补 holder 的替代。先保持寄生数量、普通抽牌量和上限，不直接改一个 `skipVisuals` 参数。
- **商人价格。** v111 `MerchantEntry.Cost` 调用 `ModifyMerchantPrice`，两目标都有该模型 Hook。议价价格可评估原生策略；购买前失败拦截与价格修改是不同职责，还须核对其他价格策略的顺序。
- **古神选项。** 两目标的 `AncientEventModel.RelicOption(RelicModel, string, string?)` 包含领取、结束页和历史流程，但为 protected；在原版涅奥实例上调用仍需窄适配，不能冒充公开入口。
- **抽牌。** 回流需要改变牌源，而原版 Draw 同时负责阻止判断、满手提示、洗牌、历史和回调。未找到等价公开牌源 Hook；值得缩小接管范围，不代表可立即删除 Harmony。
- **事件池。** 深处 `AllEvents` 原生覆写仍会经过 `GenerateRooms` 追加共享事件；`ModifyNextEvent` 也不等价于清理保存池。先查生成和读档两条路径。
- **已原生化的正例。** 蜗牛壳用格挡清除／破裂 Hook；缠丝用原生 Affliction 和 Queen 式卡牌场景；双生子换血用 `CreatureCmd.SetCurrentHp`；洞胃吞牌用完整消耗退场；熄火休息用原生订阅策略。

当前项目审查依据在 `docs/native-implementation-review-20261007.md`，此前迁移记录在 `docs/native-harmony-20261007.md`。这些记录说明具体版本的证据与限制，不冻结后续接口或实现。尤其区分“适合迁移”“已经迁移”“已经验证”。
