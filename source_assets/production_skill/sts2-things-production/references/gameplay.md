# 原生玩法、文案与多人

## 接入原版职责

新增机制、改造自定义流程或审查补丁时，先按[原版实现复用](native-implementation.md)找到同类完整调用链并核对目标版本，再采用 `MonsterModel`、`EncounterModel`、原生 MoveState、Intent、Power、Card 与游戏命令。已有 Hook 需确认分派时机与语义，缺口才由窄兼容补丁承担。

- ModelDb 原型保持不可变；实例状态写在 mutable 模型。临时费用、关键词和生成牌不污染永久牌库或 canonical 模型。
- 意图类型、次数和显示伤害与下一次实际行动一致，包含力量、形态、易伤及多段修正。状态改变时按原版刷新，并遵守已预告行动的承诺。
- Buff 使用原生层数、动态悬浮说明、闪烁和移除事件；内部调度状态可隐藏，但仍在原生生命周期里结算。不要把仅内部有用的“顽固寄生”等状态硬塞进玩家 HUD。
- 卡牌用原生生成、抽牌、移堆、消耗与显示流程。附着特效借鉴 Queen 的原生裁切／材质／解除流程，视觉应符合效果本身：缠丝可以绕过牌边，没必要长成锁链。
- 延后生效机制挂在正确的回合 Hook 上；“下回合抽牌后随机捆两张”不能在抽牌前取样。额外回合、重抽、溢出、死亡和战斗结束要有明确归属与清理。
- 插入招式保存原循环游标，执行后恢复，不把每次补牌变成从头重跑。当前已预告行动不应因一个延迟触发擅自替换，除非该机制明确允许立即改意图。
- 伤害反馈先区分原版的造成伤害、受到伤害、实际失去生命等回调，核对致死命中是否仍分派。按效果取实际结算结果，涉及生命损失时排除格挡与超杀；原生加格挡等命令在战斗结束后停止结算时，保留其结束规则，不为额外反馈强行产生第二次战斗结果。

## 可见范围和 UI

场景包含原版要求的视觉、边界、中心与意图锚点，Encounter 的 Slots 与 Marker2D 一致。镜头和动画变动后仍能选中目标、看到血条和 Buff。检查满手牌、结束回合按钮与前景遮挡，不只检查空战场截图。

动态随从、状态图标、卡面和分阶段资源进入对应预载集合。怪物死亡与战斗退出后，抓取的玩家、原牌手牌节点、装饰卡面和 UI Tween 分别按其拥有关系清理；吞噬卡牌不能只播一张装饰图而把原手牌节点留在空中。

吞牌优先沿用完整的原版消耗退场流程。`skipVisuals` 在已验证版本中还可能跳过牌堆通知和手牌节点清理，不只是关掉粒子；确需使用时先核实当前版本的行为和原节点清理归属。验证同时比较牌堆模型、手牌／出牌区节点与装饰副本，确认已移出的牌不能继续拖动。具体案例见 `docs/cave-maw-card-cleanup-20261006.md`。

音乐设置按用户约定：关闭模组指定 BGM 时恢复原版音乐，保留战斗音效。可选配置库按项目既有零依赖桥接方式接入，不把其无意变成强制前置。

## 原版文案

中文、英文的术语、句式、大小写与高亮参照原版当前本地化表。能力名称／关键词使用原版语义高亮，数值用对应动态变量；卡牌升级差值、费用和“消耗”等词条交给原版显示。

- 主说明简洁描述条件与结果，当前层数由动态文本显示。特殊细则放在相关补充悬浮说明。
- 描述卡牌效果时不附带与它无关的怪物 AI 游标或补牌排程；寄生卡保留回合结束喂养效果，血蛭的变招逻辑属于怪物行为。
- 游戏弹窗只展示玩家需要作决定的信息。按用户的横路示例，“花费 X 金币，开通这段道路？”已足够，不添加重复下半段或工程解释。
- 对齐中英键、占位符与实际结算，检查最终原生排版和动态格式，不只验证 JSON 可解析。

## 多人默认设计

本项目的玩法按 1–4 名玩家设计；配置由房主决定并同步。区分共享敌方状态与每名玩家的手牌、费用、奖励、录音、目标与选择，不能让最快的玩家抢走其他人的记录槽位。

伤害、生命、格挡、再生等沿用原版多人规则，并检查是否已经在原生命令内缩放；一次初始应用和后续追加可能不同，避免对“每人已分别触发”的固定层数再重复乘人数。

对于余影魔这类按个人输出返还的机制，返还只归属实际攻击者；宠物攻击通过原生所属玩家关系归回其主人。不能把一人的多段输出复制给全队，也不能因伤害来源是宠物而漏掉返还。

共享事件、地图操作使用原版网络选择／操作协议与同步 RNG；个人交易只改对应玩家。图像噪声、动画相位等本地效果不消耗共享战斗 RNG。房主配置、回流牌、宠物归属、取消选择、死亡途中及退出清理各按相关改动覆盖。

现有实现与兼容陷阱见 `docs/MONSTER_PIPELINE_V108.md`、`docs/native-combat-ui-20261004.md`、`docs/native-descriptions-20261004.md`、`docs/CONFIGURATION.md`；旧版文章中的玩法草案以最新源码和 [项目选择](project-decisions.md) 为准。
