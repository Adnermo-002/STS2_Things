# 骨骼与表现

## 动作质量

用户要求精良、有力度、贴合角色的完整动作。精修不是降低运动幅度，也不是增加骨数或把角色整体来回平移。

- 按形体建立承重和动力传递：蓄力、蹬地／推水、身体转动、肩肘腕或触角的先后跟随、接触、惯性和收势。
- 重型 Boss 要有重量感和稳定落点；漂浮鱼、蛾、水母可以浮动，但攻击动作和恢复要清晰。站立石柱的各层真正堆叠，受击／攻击按其要求主要前后动；坍塌才发生明确的下落。
- 不同招式有不同姿态和节奏，连击每一击都应能辨认。偷牌等特殊行为有专属动作：张掌接近玩家，在接触时握拳，所偷卡牌跟随手部。
- 默认待机、受击、攻击、施法、死亡，以及该怪物需要的蓄力、守势、恢复、变形、眩晕、消散等状态要相互连贯。

已有优质动作可参考 `TheLegacy`、`OriginFogmog`、盛碗虫族母和项目最新精修实现；学习动作语言，依目标角色重做形体动力，不机械复用同一套摆动。

## 贴图与绑定

把已接受原画拆成可重建分件，补齐动作展开后会露出的区域。爪根、脚踝、肩、髋等跨分件接缝使用连续／一致权重场；硬壳与武器保持坚硬，软体按结构弯曲。眼、嘴和贴片跟随承载网格，不能在大幅动作中漂离身体。

- 先用分件重建原姿态，再看转动后的边缘。宽多边形切片可能夹带相邻肢体的细条，静止时被遮住，运动后才变成尖刺；按实际肢体归属清理，保留必要的接缝盖片。
- 多指、多臂角色按原画定位腕部和每根指节。相邻手指需要独立动作时检查串权重，必要时拆成独立网格；骨数增加不能替代准确定位和蒙皮。
- 固定手脚支撑点时，通过关节、约束或烘焙求解维持接触，肩髋仍附着身体。主动挥击的肢体应合理释放支撑，收势后再恢复，避免为了固定末端把整条肢体平移或强行反折。

动画修复保持已批准的身份和色系。局部 edit 修补按 [美术规范](art.md) 限定区域，不能为方便绑定把原画换成另一种风格。保存分件、蒙皮和生成脚本，发布资源应能从维护源重建。

## 命中、接触与收招

- 拳头、手掌、嘴、尾巴和相应玩家目标在接触帧实际对齐，伤害、受击特效及音效以该接触时机结算。
- 多段攻击核对每一击，覆盖普通、快速和即时模式。不能只靠一次固定等待让某种速度看起来正确。
- 全屏 Boss 以实际镜头、队形和骨骼世界坐标校准，覆盖 1–4 名玩家；抓住、抛下、松手和牌上附着使用正确的所属目标。
- 回收末段和实际待机首帧要连续；检查主动画混合、IK 弯曲方向、变换约束、辅助骨轨道和角度环绕，防止结束后跳一帧或抽动两下。
- 原生包装对象明确拥有和释放关系；保持可用的轨道引用，不能释放底层对象后再留一个 Variant 假作存活引用。退出场景、结束战斗和中断抓取时清理轨道、Tween 与本地装饰。

位置或镜头调整来自当次目标；历史“玩家下移 60”“某组怪物上移 64”不是通用坐标常数。

## 表现真实状态

蓄水用身体水位、膨胀与退水，爬行用真实向玩家移动与蓄力，缠丝用覆盖卡面与牌边的实际效果，消散用身体逐步缺失。图标承担说明，身体／卡牌承担对应表现；特效材质的噪声不改变战斗 RNG。

需要验证时同时查看静态极端姿态和连续原生播放：关节接缝、隐藏残片、跳帧、承重、命中同步与完整回位。导出 GIF／视频时说明是原生渲染、离线采样还是实机。数值采样不能代替动作审美判断。

修改蒙皮或大幅动作时，可沿完整片段密集采样加权网格，检查可见区域的三角形翻面、局部塌陷、权重归一和待机闭环，再查看导出后的原生插值与混合。JSON 合法或几个关键姿态正常，不代表中间帧也正常；采样数量依动作风险选择，不以某次的骨数、帧数或断言数作为固定门槛。原生／实机验证按 [验证与交付](delivery.md) 的当次范围执行。
