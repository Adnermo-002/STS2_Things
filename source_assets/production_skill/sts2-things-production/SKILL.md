# 尖塔：琐事制作规范

把用户反复确认的制作传统用于当前任务，交付可接入游戏的精致内容。适用项目为 `STS2_Things`，常见工作区为 `D:/Things/Things-Workspace`；换机器或目录时从当前工作区与 Workbench scopes 定位，路径不是不可更改的合同。

## 先确定本轮范围

- 以当前用户指令、同一资产最新确认和项目 `AGENTS.md` 为准，再应用这里的历史归纳。用户改过的选项按最后选择实施。
- 区分设计、制作资产、实际实现、修复、审查、测试与发布。用户把外貌、数值、状态机和骨骼交给你时，自主作出一致的实现选择；只对确实影响结果且未确定的内容提问。
- 已确认的授权和选择沿用，不反复询问。Skill 本身不授予额外的发布、账户、消息发送或素材外发权限。
- 需要查原版、操作项目或游戏时，使用 `sts2-workbench`；生图使用 `imagegen`。它们提供操作流程，本 Skill 提供用户的制作标准。

## 跨内容共同标准

1. **参考真实原版。** 查当前目标版本的同类型素材、模型和渲染路径，再制作。画风不是在提示词里写一次游戏名，原生实现也不是只套一个相似图标。
2. **原版略卡通，形体明确。** 使用简化轮廓、大块明暗和克制细节；角色可以诡异、沉重或滑稽，按设定表达，避免默认做得过度凶恶或一律幼儿化。
3. **精致并有表现力。** 需要让机制、动作和反馈实际可见。精修动画要有完整身体动作、清晰命中和连贯回位，不能只靠小幅漂移与摆动。
4. **原生规则承担玩法。** 意图、Buff、卡牌、抽牌、伤害、回合、奖励及存档尽量接入原版模型与命令；本地视觉表达真实状态。
5. **数值配得上所在章节。** 同时对照整场阵容、前几轮攻击、控制、耐久和成长；为强机制安排可理解的反制与预告。
6. **交付前实际自审。** 查看原版参考和最终图／动画／界面，指出具体不符处并修改。画风未通过就回炉；只给出“画风一致”的文字不算完成。

## 完成判据

用户本轮要求的组件均有可用产物，资源引用和状态行为相符；需要自审的最终画面已经看过。验证遵守当前任务范围：明确“不测试”时不启动探针或游戏；明确要求全面测试时覆盖本轮变化及关键交互，遇到问题修复后复验。

报告实际修改、验证层级、剩余限制和文件位置，区分编译、原生探针、渲染预览、实机、真实联机与平衡通关。交付版本、安装状态和发布状态须与实际文件／工具结果一致。

## 后续维护

新的明确习惯补到相应参考，并记录出处和适用范围；被最新要求取代的内容应更新，不堆积互相矛盾的规则。当前数值、模型数量、支持版本和文件清单从项目查询，不在这里冻结。项目内 `source_assets/production_skill/sts2-things-production` 为维护源，个人 skills 目录为安装副本。
